# ERRORS — найденные дефекты и их статус

Обновлено: 2026-09-03. Аудит предыдущей версии + результат починки.

## P0 — ломали главную цепочку · ИСПРАВЛЕНО

**#1 Telegram не принимал задачи словами** — `core/telegram_bot.py`
`poll_updates` пропускал только `text.startswith("/")`. Требование «захожу в Telegram →
задаю задачу» было невыполнимо: любое обычное сообщение молча игнорировалось.
→ Свободный текст уходит в `_handle_text` → Cloud Opus.

**#2 Cloud Opus был доступен только с сайта**
`run_director` вызывался единственным местом — HTTP-роутом `POST /api/automation/director`.
При выключенном сайте оркестратора не существовало.
→ Вызывается напрямую из бота; сайт не участвует.

**#3 Результат генерации не доходил до пользователя**
Бот умел ровно один метод — `sendMessage`. Сгенерированные картинка и видео
физически не могли попасть в Telegram.
→ Добавлены `send_photo`, `send_video`, `send_media`; если Telegram не смог скачать
файл — отправляется ссылка, результат не теряется.

**#4 Не было подтверждения, перегенерации, редактирования, очереди**
Отсутствовали inline-кнопки и обработка `callback_query`.
→ Кнопки под каждым результатом + `_handle_callback` с пятью действиями;
редактирование — через ожидание следующего сообщения (`_pending`).

## P1 — HIXIIT · ИСПРАВЛЕНО (нужны переменные окружения)

**#5 Ни один путь к Higgsfield не работал**
REST-клиент бил в неподтверждённые эндпоинты и без `HIGGSFIELD_API_KEY` сразу
возвращал отказ; путь без ключа требовал включённого ПК. Рабочее подключение — MCP —
в коде отсутствовало полностью (слово «MCP» встречалось только в комментариях).
→ `core/hixiit.py` с MCP-клиентом и фолбэк-цепочкой MCP → REST → браузер → бесплатно.
⚠️ Требует `HIGGSFIELD_MCP_URL` и `HIGGSFIELD_MCP_TOKEN` в Render — см. TODO.md #2.

**#6 Модель не выбиралась под задачу**
`HIGGSFIELD_MODEL` брался статически, список `MODELS` — 8 захардкоженных строк,
которые могли расходиться с реальным каталогом аккаунта.
→ Каталог запрашивается у аккаунта (`models_explore`), кэшируется на час.
Модели, требующие входа, которого у нас нет (например YouTube-ссылку для Personal
Clipper), отфильтровываются — иначе рекомендация могла вернуть непригодную модель.

**#7 Только видео; ошибки терялись молча**
→ Добавлена генерация изображений; каждый неудавшийся путь возвращает причину,
все причины собираются в поле `tried` и доходят до пользователя в Telegram.

## P2 — память · ЧАСТИЧНО (нужно решение владельца)

**#8 Память стирается при каждом рестарте — КРИТИЧНО, НЕ ЗАКРЫТО**
`DATABASE_URL` по умолчанию — SQLite-файл, а в `render.yaml` диск не подключён
(удалён коммитом 63c255a). Файловая система Render эфемерна, поэтому при каждом
деплое пропадают ниши, контент-план, очередь, сгенерированный контент и сохранённые
API-ключи из таблицы `connections`.
→ Код готов к Postgres: `_database_url()` приводит `postgres://` и `postgresql://`
к asyncpg, `asyncpg` добавлен в зависимости, `DATABASE_URL` объявлен в `render.yaml`.
**Создание базы в Render — за владельцем.** TODO.md #1.

**#9 Cloud Opus не использовал накопленное** → `core/memory.py::build_context()`.

## P3 — мусор и мелочи · ИСПРАВЛЕНО

**#10** Недостижимая ветка `elif cmd in ("trend","trends")` — `trends` обрабатывался
на 60 строк выше. Дубликат удалён, `trend` добавлен в основную ветку.

**#11** `/set_goal` только выводил число, ничего не сохраняя. Теперь пишет в `UserProfile`.

**#12** SPA-роут `GET /{full_path:path}` отдавал HTML на любой неизвестный `/api/*`,
маскируя ошибки под успешный ответ. Теперь честный 404.

**#13** Тестов не было вообще → `backend/tests/test_smoke.py` (5 тестов: импорт всех
модулей, определение типа генерации, внятность отказа HIXIIT, сбор медиа
оркестратором, разводка кнопок).

## Известные ограничения (не дефекты)

- Публикация в Instagram/TikTok/YouTube без официальных токенов идёт через браузер-агента
  и требует включённого ПК.
- Миграций БД нет — схема создаётся через `create_all()`. При изменении моделей
  таблицы придётся приводить руками. TODO.md #5.
