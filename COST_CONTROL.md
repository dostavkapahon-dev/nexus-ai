# COST CONTROL — учёт расходов на AI

## Статус: 🟢 WORKING (BLOCK 02, реализовано)

## Единая касса
Запись расхода делает сам `core/ai_router.py` в точке `call()` — поэтому под учётом
оказывается **каждый** вызов модели, кто бы его ни инициировал. Раньше в `AgentLog`
попадали только вызовы через `BaseAgent`, а автопилот, фабрика, дирижёр, viral_research
и intent тратили бюджет мимо учёта, и цифра «Потрачено» занижалась в разы.

Ошибочные вызовы тоже записываются (`status="error"`) — видно, на чём система буксует.

## Привязка к задаче — через контекст
`core/cost_tracker.py` держит три contextvar: `current_task_id`, `current_agent`,
`current_niche_id`. `task_manager.run()` выставляет id задачи, `BaseAgent.call_ai` —
имя агента и нишу. Дальше `ai_router` сам проставляет атрибуцию, **менять вызывающий
код не нужно**. Двойного учёта нет: `BaseAgent` больше не пишет свой лог расхода.

## API (`core/cost_tracker.py`)

| Функция | Назначение |
|---|---|
| `record(model, tokens, cost, status, duration, error, agent)` | запись одного вызова |
| `spend(hours)` | сколько потрачено, токенов и вызовов за период |
| `budget_limit()` | лимит: профиль → `AI_BUDGET_USD_DAY` → 5.0 |
| `budget_status()` | потрачено / лимит / процент / `alert` (80 %) / `exceeded` |
| `by_model(hours)` | что именно съедает бюджет |
| `by_agent(hours)` | кто инициирует расход |
| `maybe_alert()` | предупреждение в Telegram на 80 % и при превышении, не чаще раза в сутки на уровень |

## Бюджет
Дневной лимит хранится в `UserProfile.budget_usd_day` (добавлен миграцией
`1b7757da0617`); 0 — берётся из `AI_BUDGET_USD_DAY`, по умолчанию $5/сутки.
Меняется в дашборде → «Расходы» или через `POST /api/cost/budget`.

Алерты идут в Telegram: ⚠️ на 80 % и 🛑 при исчерпании.

## Реальный режим economy/premium
`ai_router.pick_model(role, default, mode)` выбирает модель из `ECONOMY_MODELS`
или `PREMIUM_MODELS` по `UserProfile.ai_mode`. Раньше переключатель был фикцией:
агенты брали модель только из `prompt_store`. Теперь:

1. Модель, **явно** заданная пользователем в кастомном промпте, — приоритет (флаг
   `custom_model` из `prompt_store.get_prompt`).
2. Иначе решает `ai_mode`.

## Точность подсчёта токенов
| Провайдер | Источник |
|---|---|
| Anthropic | `usage.input_tokens + output_tokens` — точно |
| OpenAI / DeepSeek / Perplexity / free | `usage.total_tokens` — точно |
| Google Gemini | `resp.usage_metadata.total_token_count` — **точно** (была эвристика `len(text.split())*2`) |

Эвристика осталась только как запасной путь, если провайдер не вернул `usage`.
Free-провайдеры тратят квоты, а не деньги — `cost = 0`, но токены и вызовы считаются.

## Где видно
- **Дашборд → «Расходы»**: бюджет с прогресс-баром, период (сутки/неделя/месяц),
  разбивка по моделям и агентам, поле лимита.
- **Telegram `/cost`**: те же цифры текстом.
- **API**: `GET /api/cost?hours=24`, `POST /api/cost/budget`.
- **Страница «Задачи»**: расход по каждой задаче отдельно.

## Как система экономит (работает)
- 6 бесплатных провайдеров первыми в `FALLBACK_CHAIN`.
- `ECONOMY_MODELS` по умолчанию (deepseek-chat, gemini-flash-lite, gpt-4o-mini).
- `self_critique.pre_check` — уточнение задачи дешёвой моделью до дорогой генерации.
- `skills_store.context_for` — память вместо повторного research.
- Раскадровка через Pollinations (бесплатно, 0 токенов).

## Тесты (`tests/test_cost.py`, 8 шт.)
Запись в AgentLog · **вызов вне BaseAgent попадает в учёт** (главная дыра аудита) ·
расход приписывается запущенной задаче · ошибка вызова тоже журналируется ·
бюджет поднимает `alert` и `exceeded` · разбивки по моделям и агентам ·
`ai_mode` реально выбирает набор моделей · API расходов и установка лимита.

## Медиа в кассе (BLOCK 08)
Генерация изображений и видео — самая дорогая часть системы, но раньше проходила
мимо учёта. Теперь каждая генерация записывается через `media_generator._track_media`
с агентом `media`; неудачные попытки фиксируются со статусом `error` и нулевой ценой.

Ориентировочный прайс (`MEDIA_COST`): heygen $0.30 · runway $0.25 · higgsfield $0.20 ·
dalle3 $0.04 · imagen $0.03 · elevenlabs $0.02 · stability $0.01 · pollinations $0.

`by_kind()` показывает расход раздельно: текст и медиа — смешивать их в одной цифре
бессмысленно, потому что одно видео стоит как сотни текстовых вызовов.
