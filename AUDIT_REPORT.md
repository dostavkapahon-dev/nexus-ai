Агенты уже **не** независимые системы: доступ к ним идёт через
`core/dispatch.py::delegate`, публикация вынесена в очередь (агенты сами в
площадки не пишут — это проверяется тестом `test_agent_registry.py`).

### Модели ИИ и маршрутизация

`core/ai_router.py` — единая точка. Цепочка: шесть бесплатных провайдеров
(NVIDIA, Groq, Cerebras, OpenRouter, Mistral, GitHub Models) → Gemini →
DeepSeek → GPT-4o-mini → Claude. Модели без ключа пропускаются, конкретный id
подбирается из каталога провайдера, 429/quota/`not found` переключают модель без
повторов, прочие ошибки — три попытки с задержкой. Расход пишется в единую кассу
(`core/cost_tracker.py`). Последнее звено — `core/ai_escrow.py`: если не ответил
никто, запрос человека уходит Клоду в аккаунт Claude Code, а не теряется.

### Хранение доступов

`core/credentials.py` + `core/secrets.py`: значения шифруются Fernet
(`NEXUS_SECRET_KEY`, префикс `enc:v1:`), лежат в таблице `connections`, в API
отдаются замаскированными. **В браузере секретов нет** — в `localStorage`
хранится только токен входа (`frontend/src/lib/api.js:6`).

### Задачи и фон

`core/task_manager.py`: `TASK`-запись на каждую операцию, статусы
CREATED / RUNNING / WAITING / COMPLETED / FAILED / CANCELLED, шаги, стоимость,
`spawn` для фонового запуска, `recover_stuck` при старте. Планировщик
(`core/scheduler.py`) ведёт 11 регулярных заданий, очередь публикаций
разбирается каждые 10 минут. Всё это живёт на сервере — компьютер пользователя
не нужен: браузерные действия умеет делать `core/server_browser.py`
(`NEXUS_SERVER_BROWSER=1` в `render.yaml`), ПК-агент — только запасной путь.

### Веб и Telegram — одна система

Один backend, одна БД, одна очередь. Веб: 7 разделов (Главная, Командный центр,
Подключения, Агенты, Контент, Настройки, API/Credentials), старые адреса живут
через редиректы (`frontend/src/App.jsx`). Telegram: команды, согласование
контента кнопками, подключение каналов мастером.

## 3. Что существует только визуально

Проверено чтением кода, не предположением:

- **Кнопка «Фабрика (превью)»** в меню бота запускала `dry_run`: конвейер
  отрабатывал, но шаг согласования пропускался, и ролик не приходил никуда.
  Исправлено в этой ветке (коммит `dc9bbca`).
- **`/create`** при пустом контент-плане отвечал «запусти /analyze» — тупик,
  фабрику не вызывал. Исправлено там же.
- **Свободный текст в боте** отвечал обещаниями («сгенерирую, смонтирую,
  опубликую»), которые никто не исполнял. Исправлено там же.
- **Автопродление токена Instagram Login** не срабатывало никогда (`days_left`
  у этого типа токена всегда пуст). Исправлено ранее в этой ветке.
- **`can_publish`** у Instagram был захардкожен `True`. Исправлено.
- **Higgsfield на сервере** — интеграция есть, но по непроверенным эндпоинтам;
  фактически ролики делает внешний исполнитель через очередь `ProductionJob`.

## 5. Порядок исправления

   настройка исчезнет при следующем деплое.
2. **BLOCK 5 — task engine** (P0 #2, #3, P1 #5): watchdog, живой статус,
   человеческие ошибки.
3. **BLOCK 11 — Telegram CREATE** (P0 #4).
4. Далее: агенты как worker-ы одного оркестратора, память проекта, стратегия по
   одной фразе, веб-дашборд, security-аудит целиком.

Правило из ТЗ соблюдается: следующий блок не начинается, пока предыдущий не
проверен тестами и не зафиксирован отдельным коммитом.
